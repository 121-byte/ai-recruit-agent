# 记忆检索阈值调优过程

本文记录 2026-08-05 对长期记忆混合检索的离线评估、噪声定位与阈值调优过程。配套明细报告见 `eval-reports/memory-2026-08-05.md`。

## 背景问题

初始评估中，记忆检索的 `Recall@5` 较高，但 `Precision@5` 偏低。典型表现是：向量召回返回了语义上宽泛相近、但不能直接回答问题的记忆；关键词召回只搜 `memory_value`，对 `memory_key` 和 `tags` 利用不足；评估用例依赖数据库自增 ID，重新 seed 后存在标签漂移风险；评估调用真实 `retrieve` 会刷新 `access_count`、`last_access` 和 TTL，导致评估过程污染记忆状态。

因此本轮调优目标不是单纯追求最高召回，而是在尽量保留相关记忆覆盖的前提下，减少 Top5 中的无关记忆噪声。

## 调优动作

1. 评估口径修正：`MemoryRetrievalEvalTest` 改用稳定的 `memory_key` 标注相关记忆，并调用 `retrieveReadOnly`，避免评估触发命中续期。
2. 关键词增强：关键词检索范围从 `memory_value` 扩展到 `memory_key`、`memory_value` 和 `tags`，并对中文查询做轻量停用词清理与拆词。
3. 记忆专用 rerank 指令：新增 `rerankMemory`，提示 rerank 优先选择能直接回答当前问题的记忆，而不是沿用候选人匹配的通用指令。
4. 向量召回阈值：新增 `app.memory.vector-min-similarity`，低于阈值的向量结果不进入候选池。
5. 最终直接相关性阈值：新增 `app.memory.final-min-direct-match-score`，在 rerank 后按查询关键词、业务槽位和来源信号过滤最终结果。

## 实验结果

| 方案 | Precision@5 | Recall@5 | 观察 |
|---|---:|---:|---|
| baseline，不加阈值 | 0.4813 | 0.8417 | 召回覆盖高，但 Top5 噪声明显 |
| 仅向量阈值 0.50 | 0.5031 | 0.8604 | 略微提升准确率，说明部分弱相关向量噪声被截断，但最终结果仍有泛化记忆 |
| 仅向量阈值 0.55 | 0.5156 | 0.8703 | 聚合指标略高，但一次 embedding 调用异常导致个别查询空结果，稳定性需继续观察 |
| 向量 0.50 + 最终阈值 0.55 | 0.7141 | 0.5797 | 准确率高但过滤过严，大量相关记忆被漏掉 |
| 向量 0.50 + 最终阈值 0.30 | 0.6604 | 0.7844 | 相比 baseline 明显降噪，但部分年限类问题仍不够稳 |
| 向量 0.50 + 最终阈值 0.40 | 0.7000 | 0.8000 | 当前最均衡，Precision 明显提升且 Recall 仍保持在 0.80 |

最终推荐先使用：

```properties
app.memory.vector-min-similarity=0.50
app.memory.final-min-direct-match-score=0.40
```

代码默认值仍为 `0.0`，即默认不启用阈值，避免直接改变现有运行行为。需要启用时通过配置覆盖。

## 关键样例

| 查询 | 调优后表现 | 说明 |
|---|---|---|
| 张三参与的项目 | Precision@5=1.0000，Recall@5=1.0000 | 最终结果集中到 `project:trade-system`、`zhangsan:project` |
| 核心交易系统项目经验 | Precision@5=0.7500，Recall@5=1.0000 | 项目与候选人经验均能召回，噪声明显减少 |
| 五年以上经验候选人 | Precision@5=1.0000，Recall@5=0.5000 | 年限槽位补充后能保留候选人与经验记忆，但召回仍偏保守 |
| 人才分层情况 | Precision@5=1.0000，Recall@5=0.2000 | 返回了总结性 `note:talent-tier`；若期望展开所有候选人，需调整评估标签或查询意图 |
| 张三的教育背景 | Precision@5=0.2000，Recall@5=0.5000 | 仍会混入张三技术、offer、面试等同实体噪声，后续可增强实体+槽位联合约束 |
| Python方向的候选人 | Precision@5=0.2500，Recall@5=0.5000 | 方向类查询仍容易被通用推荐记忆干扰，后续可加岗位方向词典或负向过滤 |

## 结论

本轮调优将 `Precision@5` 从 0.4813 提升到 0.7000，同时 `Recall@5` 从 0.8417 小幅下降到 0.8000。这个结果适合写成“构建评估闭环并显著减少无关记忆干扰”，不宜表述为“检索准确率达到业界高水平”。

后续如果继续提升，可以优先做三件事：扩充评估集并拆分 train / held-out；给实体类查询加入更强的“实体 + 槽位”约束；对人才分层、方向推荐这类集合型查询单独定义评估口径。
