## 一、项目背景与定位

这是一个面向招聘业务的 AI Agent 应用，目标是用 LLM Agent 把招聘流程中的重复性脑力劳动（岗位画像、简历结构化、候选人匹配、面试出题与评估、候选人触达）自动化串联起来，而不是单纯做一个"聊天框 + CRUD"。

系统的两条主线：

1. **业务线**：岗位 → 简历 → 匹配 → 面试 → 外联，构成招聘漏斗，各环节都有 LLM 参与增强。
2. **Agent 线**：一个多范式对话 Agent 作为统一入口，按用户意图分流到"闲聊直答 / 单工具 ReAct / Supervisor 多专家协作 / ReWOO 批量并行 / HITL 人工确认"五种执行范式，避免一刀切走 ReAct 造成 token 与延迟浪费。

底层以 Spring Boot 3 + AgentScope 2.0 为运行时，PostgreSQL+pgvector 承载结构化数据与向量，Redis 承载短期会话记忆，RabbitMQ 承载异步简历分析任务，前端为 Vue 3 + Ant Design Vue。

> 项目复刻自 AgentScope 招聘示例（`pom.xml` 描述：`ai-recruit — AgentScope 复刻`），并在此基础上做了工程化封装与多范式编排。

## 四、整体架构与请求流

### 4.1 分层

- **接入层**：`@RestController`（业务模块）与 SSE 控制器（Agent / 面试官）。统一响应经 `ApiResponseAdvice` 自动包裹，全局异常经 `GlobalExceptionHandler` 映射为 `ApiResponse`。
- **应用层**：各 `module/*/application/*Service`，编排业务流，调用 LLM/检索/数据。
- **Agent 层**：`agent/core/ConversationAgentService` 是对话总编排，按意图分发到 ReAct / Supervisor / ReWOO 等。
- **基础设施层**：`infra/llm`（LLM 网关）、`infra/retrieval`（Embedding/Rerank）、`infra/fileparser`（文件解析）、`infra/observability`（LangFuse）。
- **数据层**：`dal` 的 MyBatis-Plus Mapper + 三类 TypeHandler（pgvector / Long[] / String[]）。
- **记忆层**：`memory` 跨会话的短期/长期/图谱记忆与混合检索。

### 4.2 典型请求流（业务接口）

```
HTTP → Controller → Service → (LLM 网关 / 检索 / Mapper) → ApiResponseAdvice 包裹 → 响应
```

### 4.3 典型请求流（Agent SSE 对话）

```
POST /api/agent/chat/stream (SSE)
 → AgentChatController.chatStream
 → ConversationAgentService.stream (Flux.defer，订阅级副作用)
   1) Redis 短期记忆 addMessage(user)
   2) 解析/创建会话，发 session 事件回传真实 sessionId
   3) IntentRouter.classifyWithUsage 意图分类（分层置信度 + LLM 兜底）
   4) ContextAssembler.assemble 注入记忆快照到 RuntimeContext
   5) 按 IntentType 分流：
      CHITCHAT → 直答流式；CLARIFY → 澄清；BATCH_INDEPENDENT → ReWOO；
      SINGLE_TOOL → ReAct；COMPOSITE → Supervisor；HITL → 拦截+快照
   6) Agent 事件 → AgentEventSseMapper.toSse → SSE 事件流（PII 脱敏）
   7) concatWith(stats, done)；doOnComplete 落库消息+token、LangFuse、Trace
   8) finalizeTurn 异步：记忆提取 + 巩固触发 + 缓存清理
```

## 五、功能与实现流程

### 5.1 认证与权限（identity）

**入口**：`AuthController`(`/api/auth`)、`UserAdminController`(`/api/admin/users`, `@SaCheckRole("OPS")`)。

**登录流程** (`AuthService.login`, `AuthService.java:48-75`)：
1. Mock 模式直接返回桩 token `mock-token-<millis>` + HR 张三。
2. 真实模式：按用户名查 `sys_user` → `BCryptPasswordEncoder.matches` 校验 → 检查 `disabled` → `StpUtil.login(userId)`（Sa-Token）→ 返回 `StpUtil.getTokenValue()` + 角色码列表。

**鉴权**（`SaTokenConfig.java:21`）：`SaInterceptor` 拦截 `/api/**`；Mock 模式跳过登录。RBAC 采用方法+路径规则：OPS 管理用户与岗位写操作；HR 管理匹配/出题/面试官/HITL 确认/评估；SSE 订阅校验路径 userId 与登录 id 一致（或有 `events:subscribe:all` 权限）。仅引入 `spring-security-crypto`（BCrypt），未启用完整 Spring Security。

**HR 偏好**（`HrPreferenceService`）：UPSERT 写入 `hr_preference.preferenceJson`，供匹配评分与 Agent 上下文使用，含过期清理。

### 5.2 岗位（job）

**CRUD**（`JobController` `/api/jobs`）：列表（带 keyword/status/department/level 时走 `search` 自定义 SQL，否则全量）、部门/职级聚合、单条、增改删。`JobProfileService` 是纯 MyBatis-Plus 包装，无 LLM 依赖（类 Javadoc 明示）。

**岗位分析**（`POST /api/jobs/{id}/analyze` → `JobAnalysisService.analyze`, `JobAnalysisService.java:46-98`）：
1. 加载 `JobProfile`，空则返回错误。
2. 构造 system prompt，要求严格 JSON 输出四件套：`weight_matrix`（技能→0-1 权重）、`role_graph`（核心职责/协作对象/汇报关系）、`growth_path`（成长阶段）、`requirements`（硬性要求）。
3. user 内容 = `岗位标题 + JD`。
4. `deepSeek.chatJson` 单次 LLM 调用（`chatJson` 自动追加"严格 JSON 输出"后缀）。
5. `JsonGuard.parseJsonSafe` 容错解析，失败用空对象兜底。
6. 将三个 JSON 节点写回 `JobProfile` 实体。
7. `embeddingService.embed(jdText)` 生成 JD 向量回写 `job_profile.embedding`（失败 `Throwable ignored` 吞掉，属尽力而为）。
8. 持久化并返回结构化画像。

**产出意义**：岗位画像的 `embedding` 是候选人匹配 Stage-1 召回的输入；`weight_matrix` 等可用于后续匹配权重与展示。

### 5.3 简历上传与解析（resume）

详见 `docs/亮点实现细节.md`，此处精简流程：

1. **上传**（`ResumeController` `POST /resumes/upload`，`multipart/form-data`）：前端显示传输进度，`beforeUpload` 返回 `false` 由页面统一提交。
2. **文本提取**（`FileParserUtil`, `FileParserUtil.java:36`）：按格式分流——TXT 直读；PDF 主走 PDFBox（纯文本利于结构化，避免多栏转 Markdown 碎片），失败回退 MarkItDown；Office 文档主走 MarkItDown（保留标题/列表/表格语义），DOCX 可回退 POI。MarkItDown 路径把字节写临时文件，`ProcessBuilder` 调 `scripts/parse_resume.py`，读 stdout 后删临时文件。统一产出 `rawText`。
3. **快速预结构化**（`QuickInfoExtractor`, `QuickInfoExtractor.java:13`）：纯正则毫秒级提取姓名/手机/邮箱/学历/学校/专业/工作年限/意向岗位，连同 `rawText` 创建简历记录，状态 `parsed`。
4. **深度分析触发**（`POST /resumes/{id}/analyze` → `ResumeAnalysisController`）：真实模式+MQ 可用时创建 `RESUME_ANALYSIS` 任务投递 RabbitMQ，立即返回 `taskId`+`PENDING`；前端每 2s 轮询任务状态，最多 90 次。Mock/无 MQ 时同步降级。
5. **MQ 消费**（`AnalysisTaskConsumer`, `@ConditionalOnProperty(app.mock.enabled=false)`，`@RabbitListener`）：标记 RUNNING → `ResumeAnalysisService.analyzeFull`（4+1 轮 LLM）→ 全文 Embedding → `DocumentChunkService` 语义分块+向量。失败标 FAILED。向量失败不阻断已完成的回写。
6. **4+1 轮分析**（`ResumeAnalysisService.analyzeFull`）：①结构化抽取（按 `PositionCategories` 归一意向岗位类别）→ ②隐性洞察 → ③风险识别 → ④潜力评估 → ⑤结果自校验。第 1 轮字段以"非空覆盖"策略修正正则预填，避免模型遗漏清空已有信息。各轮结果+校验+时间序列化写入 `parsedJson`，状态置 `analyzed`。
7. **向量化**：全文向量写 `resume.embedding`（粗粒度整体相似度）；按 `basic_info/skills/work_exp/projects/education` 五类语义切分，每块独立向量写 `document_chunk`（细粒度定位证据）。无结构化 JSON 时以全文 `full` 单块兜底。

**关键边界**：上传不自动触发深度分析；扫描件 PDF 无可靠 OCR；任务状态为内存级 `TaskStatusManager`，重启不可恢复。

### 5.4 候选人匹配（match）

**入口**：`CandidateMatchController` `/api/matches`，核心 `POST /api/matches/job/{jobId}/run` → `CandidateMatchService.matchForJob` (`CandidateMatchService.java:80-150`)。四阶段：

**Stage 1 — pgvector 召回 + 方向预过滤** (`:88-94`)
- 取 `job.getEmbedding()`；空则临时 `embeddingService.embed(title+" "+jdText)`（注意：此处**不落库**，与岗位分析不同）。
- `extractPositionFilters(title)` (`:214-229`)：从标题纯子串扫描出方向词（java→Java、前端/vue→前端、后端→后端、算法/ai→算法 等）。
- `VectorSearchService.searchCandidates(jobEmb, 20, filters)` (`VectorSearchService.java:60`)：有 chunk 走 chunk 级 pgvector 检索（`document_chunk.embedding <=> ?::vector`，按 `parent_id` GROUP BY 取最小距离，JOIN `resume` 用 `intended_position` ILIKE/OR 多模方向过滤）；无 chunk 走内存全表 cosine 兜底。

**Stage 2 — 条件性 rerank** (`:96-110`)
- 仅当 `pool.size() <= 10` 才进入 rerank。
- ⚠️ **已知缺陷**：`RerankService.rerank` 在 `documents.size() <= topN` 时短路返回原序（`RerankService.java:71`），而此处 `topN` 传的是 `docs.size()`（`:102`）。两者条件叠加，导致**百炼 rerank 端点在匹配链路中从不被真正调用**——rerank 实为死代码（详见「已知缺陷」）。

**Stage 3 — LLM 三维评分** (`:112-121`)
- 仅对前 5 名评分。每名：Java cosine 算 `vectorScore`；`llmScore` 用 `chatJson` 求 `skill/experience/soft` 三维 0-100 分 + `reason`；解析失败回退 `50 + 30*vectorCosine`。
- 透明加权：`final = skill*0.4 + exp*0.3 + soft*0.2 + vector*0.1`，按降序排序。

**Stage 4 — 落库 + 自动建面试** (`:124-142`)
- 每名写 `CandidateMatch`（五维 BigDecimal + `matchDetails`）。
- ⚠️ `match_details.reason` 被硬编码为字面量 `"LLM 三维评分 + 透明加权"`（`:291`）——prompt 里请求的 `reason` 字段被 `llmScore` 丢弃，**当前没有逐候选人的自然语言匹配理由**。
- 自动为每名匹配创建一条 `Interview`（round=1, status=pending）。

### 5.5 面试与 AI 面试官（interview）

**面试 CRUD**（`InterviewController` `/api/interviews`）：列表/按岗/详情/创建(默认 pending)/状态流转/出题/题目列表/HR 采纳题/会话查询。`InterviewService` 是纯 Mapper 包装。

**AI 出题**（`POST /interviews/{id}/questions/generate` → `QuestionService.generateQuestions`, `QuestionService.java:55-108`）：
- 加载 Interview + Job + Resume；system prompt "你是技术面试官"，要求 5 题（technical×2 / project×2 / behavioral×1），每题带 `follow_ups`，严格 JSON。
- `deepSeek.chatJson` → 逐题 `questionMapper.insert`（单题失败不影响其余）。

**AI 面试官 SSE**（`InterviewAgentController` `/api/interview-agent`）：
- `start`：`InterviewAgentService.startInitialInterview`（`:62-129`）加载/创建 `InterviewSession`，调用 `deepSeek.chat`（开场白），用 `statusBar.appendTo` 在 user 内容尾部追加 `<agent_status>` 块，落库消息，置 interview 状态 `scheduled`。
- `answer/stream`（SSE）：`streamProcessAnswer`（`:198-214`）用 `deepSeek.chatStream` 流式输出逐 token 包成 `event("text")` 的 SSE；⚠️ 流式输出**不回写**会话消息（只有非流式 `processAnswer` 持久化）。
- `answer`（非流式）：`processAnswer`（`:135-192`）求 JSON `{score, feedback, next}`，追加 interviewer 消息落库。
- `end`：`endInterview`（`:219-235`）仅 `currentRound += 1`；⚠️ 不写终止状态。
- `assist` / `report`：`getReport`（`:271-310`）求 JSON 报告（overall/tech/comm/problem_solving/culture_fit + strengths/risks + hiring_suggestion + summary），⚠️ 每次 `reportMapper.insert` 新增一行（无 upsert，重复调用产生重复报告）。

**面试状态栏（亮点，纯代码无 LLM）** — `InterviewStatusBar`（`InterviewStatusBar.java`），可配置 `interview.total-minutes/follow-up-limit/wrap-up-threshold`。`build(session)` 通过关键词正则与时长算术产出 `<agent_status>` 块：
- `classify` 按关键词将问题分为 技术/行为/其他（TECH_KEYWORDS ~36 词优先，BEHAVIOR_KEYWORDS 次之）；
- `inferStage` 推断 开场/技术深挖/行为综合/收尾；
- `computeRemainingMinutes` 推剩余时长；
- `computeFollowUpDepth` 统计同维度连续追问深度；
- `inferStrategy` 输出"追问达上限换维度""剩余≤阈值优先收尾"等动作提示。
- 设计要点：状态块放在 **user 内容尾部**而非 system prompt，**不破坏 KV cache**；给模型的是"读数 + 动作建议"而非硬指令。

### 5.6 外联（outreach）

外联模块**没有 Controller**，仅 `OutreachService`，暴露通过 Agent 工具 `agent/tool/OutreachAgentTool`（`@Tool(name="generateOutreach"/"generateBatchOutreach")`）。

**触达内容生成**（`OutreachService.generateAndCreatePersonalized`, `OutreachService.java:111-158`）：
- 加载 Job + Resume；system prompt "你是资深招聘 HR，撰写 150 字内真诚邀约消息"；user = 标题+薪资+地点+候选人名+简历前 200 字。
- `deepSeek.chat`（非 JSON）单次调用；失败回退模板 `"您好，我们正在招聘 {title} 岗位，期待与您沟通。"`。
- 落 `Outreach` 实体（status=draft, batchId=single-<millis>）。
- 批量：`generateAndCreateBatch`（`:164-186`）共享 `batchId`，**N 次串行 LLM 调用**（无并行）。

**生命周期**：`draft → sent`（`confirmBatchSend` 批量翻转）→ `replied/ignored`；`transitionStatus` 带 from→to 守卫。`funnelByJob/kanbanStats` 提供漏斗与看板聚合，供仪表盘消费。

### 5.7 对话 Agent（核心子系统）

详见 `agent/`。下面按子能力拆解。

#### 5.7.1 多范式分流

`ConversationAgentService.stream`（`ConversationAgentService.java:133-209`）按 `IntentType` 分流（参见「整体架构 4.3」）：

| IntentType | 处理 | 范式 | LLM 调用 |
| --- | --- | --- | --- |
| CHITCHAT | `streamChichat` | DeepSeek chatStream 直答（取 Redis 最近 3 条历史） | 1 |
| CLARIFY | `streamClarify` | 固定澄清话术 | 0 |
| SINGLE_TOOL | `streamReAct` → `RecruitmentAgentService` HarnessAgent(maxIters=3) | ReAct | ≤3 轮 |
| COMPOSITE | `streamSupervisor` → `SupervisorAgentService`(maxIters=5, Agent-as-Tool 4 专家) | Supervisor 多专家 | ≤5 轮 |
| BATCH_INDEPENDENT | `streamBatch` → `ReWooExecutor` | ReWOO：规划→并行(4 线程池)→汇总 | 规划+汇总 |
| HITL | `formatHitl` + `confirmHitl` | 快照+异步恢复 ReAct | 0（询问时）/ ReAct（确认后） |

#### 5.7.2 意图路由（分层置信度）

`IntentRouter.classifyWithUsage`（`IntentRouter.java:120-140`）：
1. `matchWithEmbedding`：截断(≤2000 字)用户消息 → Embedding → 与各 `IntentType` 静态锚点余弦，得 best 与"不同类型次优"。
2. **HIGH 直返**：`bestScore >= 0.90` 且 `best - second >= 0.12` 且 best 非 HITL → 直接返回，**零 LLM token**。
   > ⚠️ 代码常量 `:40-42` 为 0.90/0.65，但 Javadoc 写 0.85/0.65——以代码为准。
3. **MID Top-2 LLM 验证**：`bestScore >= 0.65` → ~60 token prompt 在两候选意图间二选一，`JsonGuard` 解析，失败→clarify。
4. **LOW 全量五分类**：完整 LLM 分类，失败→clarify。
5. **CLARIFY 兜底**：返回 `Intent.of(CLARIFY, 0)`，对话侧发澄清话术，永不进入工具链。
6. HITL 故意不靠 embedding 自动确认——`bestType() != HITL` 守卫强制高风险输入走 LLM 复核。

> ✅ **动态锚点自学习已接入（默认关闭灰度）**：`DynamicAnchorPool` 注册为 `@ConditionalOnProperty(app.intent.dynamic-anchor.enabled=true)` 条件 Bean，默认关闭。开启后 `IntentRouter` 可选注入并在 `matchWithEmbedding` 合并动态锚点计分；低置信全量分类路径 LLM `confidence ≥ 0.9` 且非 HITL/CLARIFY 时直接 `add` 回写（脱敏文本 + 复用已算向量）。最久未命中淘汰（删 `lastHitTime` 最旧，非最早插入）、语义去重 `cosine ≥ 0.90`、`@Scheduled` 每 5 分钟 flush、`@PostConstruct` 加载。未开启时 `IntentRouter` 退化为纯静态锚点，行为不变。

#### 5.7.3 HITL 权限

`RecruitmentPermissionService`（`:28-47`）建 `PermissionContextState`：`listJobs/analyzeJob/getQuestions/search/analyze/web/outreach/interview` → ALLOW；`matchCandidates/generateQuestions` → ASK。挂载到两个 HarnessAgent，命中 ASK 产出 `RequireUserConfirmEvent` → `hitl` SSE 事件。`confirmHitl` 恢复 `ContextSnapshotService` 中的快照，异步重跑 ReAct，恢复期 token 加回最新 assistant 消息。

#### 5.7.4 SSE 事件映射与 PII 脱敏

`AgentEventSseMapper.toSse`（`:87-277`）将 AgentScope 约 28 类事件映射为 14 类前端 SSE 事件：`text/thinking/tool_call/tool_result/data/trace/hint/done/hitl/plan/stats/session/stop/error`。关键：`TextBlockDelta`/`ToolResult` 经 `maskPii`（`:321-339`）脱敏——手机→`138****8888`、身份证→`######********####`、邮箱→`a***@c.com`。脱敏在 SSE 层做，因 AgentScope `Msg` 不可变无法在中间件改。`AgentEventPublisher` 另把原始 `AgentEvent` 发 Spring 应用事件，解耦异步监听。

#### 5.7.5 上下文装配与短期记忆

- 短期：`RedisSessionMemory`（`memory/RedisSessionMemory.java:34`）List `agent:session:{id}`，TTL 3600，cap 10；≥8 触发 `compressHistory` 用 `chatFast` 摘要压缩，保留近 4 条 + 摘要行。无 Redis 时回退内存 Map。
- 装配：`ContextAssembler.assemble`（`:49-106`）取偏好 Top5（按 importance）+ `HybridMemoryRetriever.retrieve` Top5，去重后注入 `RuntimeContext.memorySnapshot`，附"非指令"免责声明。失败非阻断。
- 压缩：两 Agent 配 `CompactionConfig.triggerMessages(20)`，AgentScope 满 20 条自动压缩上下文。

#### 5.7.6 护栏与 Reflexion 反思

两者均挂载在 ReAct/Supervisor/四专家上。

- **输入护栏** `ConversationGuardrail`（`onAgent`，执行前）：`PROMPT_INJECTION` 正则识别"忽略上述指令"/角色劫持/泄露系统提示；`BIAS_INPUT` 识别性别/民族/户口/学历歧视。命中→发 `guardrail_blocked` 事件，Agent 不执行，SSE 映射为 `error`。
- **Reflexion** `ReflexionMiddleware`（`onActing`，工具执行后）：仅对 `matchCandidates/generateQuestions/generateOutreach` 三关键工具。累积 `ToolResultDelta` → `chatFast` 用 `EVAL_PROMPT` 做"相关性/完整性/合规性/overall"四维评估；`overall >= 0.75` 放行；否则按 toolCallId 计数（`MAX_RETRIES=2`）注入 `HintBlockEvent` 反思提示让 Agent 调参重试，超限接受结果。评估失败返回 1.0，永不阻断主流程。

#### 5.7.7 落库与追踪

- **消息+token**：`finalizeTurn`（`:547-576`）存 user/assistant 两条 `ChatMessage`（assistant 连同 reasoning 链与 output token），`touch` 刷新会话时间。`ChatSessionService.tokenStats` 按角色聚合 token；HITL 恢复 token 加回最新 assistant 消息。
- **Agent Trace**：`AgentTraceAspect`（`@Around @annotation(Tool)`）每次工具调用插一行 `AgentTrace`（工具名/截断入参 2000/延迟/状态）；`streamAgentEvents.doOnComplete` 记 per-turn 汇总，供 `/chat/explain` 与仪表盘消费。
- **LangFuse**：可选，默认关闭，`traceGeneration` 异步 POST 到自托管 ingestion，全部失败吞掉，不影响主流程。

### 5.8 记忆系统（memory）

**四层**：感知(单次 UserMessage) → 短期(Redis List，渐进压缩) → 长期(PG+pgvector `memory_entry`) → 实体/图谱(`memory_graph` 双向边)。

**长期记忆自动提取**（`AutoMemoryExtractor.java:31`）：每轮对话后异步——短消息跳过、`TRIGGER_KEYWORDS` 预过滤、长度截断 → `chatFast`+`JsonGuard.extractJson` → 同 key 同 value 去重 upsert。带 `INJECTION_IN_MEMORY` 正则拦截注入短语。

**巩固**（`ConsolidationScheduler` 每小时 + 会话结束触发，待巩固 ≥10 条）：`MemoryConsolidationAgent` `@Transactional` 七步——分类/冲突消解/标签/图谱边/语义合并(>0.95)/重要性评分/摘要。`claimTask` 用 `UPDATE ... WHERE status='pending'` CAS 实现多实例抢占。

**双重遗忘**：`MemoryDecayJob` 每天 03:30，`importance *= 0.95`（保护 ≥0.7），<0.05 归档；`MemoryForgettingService` 每小时，14 天未访问 ×0.8，<0.15 归档，超 200 条按 importance+updated LRU 驱逐。

**五级混合检索**（`HybridMemoryRetriever.java:46`）：
1. 向量检索（`1 - (embedding <=> ?::vector)`，Top10，排除 archived）
2. 关键词检索（ILIKE，rawScore 0.5）
3. 图谱游走（`memory_graph` 双向 UNION，按边权）
4. RRF 融合（k=60，三路）× `recencyFactor = exp(-days/30)`（30 天半衰期）× `importanceFactor`（≥0.7→1.5，≤0.3→0.5）
5. 结果 >5 时 `RerankService.rerank` 精排取 Top5（与匹配链路不同，此处 topN=5 < documents，rerank 真正生效）
6. ThreadLocal LRU 缓存同 query。

> 图谱标签当前仅 debug 日志，未持久化（`MemoryConsolidationAgent:153`）；图谱边已持久化供游走。

## 七、亮点技术

1. **意图驱动的多范式 Agent 编排**：闲聊直答不进工具链省 token；批量独立任务走 ReWOO 一次规划并行执行；复合任务走 Supervisor 多专家协作（每个专家独立 sysPrompt+Toolkit+上下文，缓解单 Agent 工具过多误选与 maxIters 截断）。
2. **分层置信度意图路由**：高置信直返零 LLM、中置信 Top-2 验证、低置信全量分类、HITL 强制 LLM 复核——在准确率与 token 成本间取衡。
3. **四层记忆 + 五级混合检索**：向量+关键词+图谱游走→RRF 融合→时间衰减×重要性加权→rerank 精排，跨会话语义记忆；30 天半衰期模拟遗忘曲线；高重要性记忆永久保护。
4. **LLM 驱动的 7 步记忆巩固 + 双重遗忘**：分类/冲突消解/标签/图谱/合并/评分/摘要；日级衰减 + 时级容量驱逐；多实例 CAS 抢占任务。
5. **可解释的候选人匹配链路**：pgvector 召回+方向预过滤→（条件性）rerank→LLM 三维评分→透明加权（skill 40%/exp 30%/soft 20%/vector 10%）。
6. **Agent 安全与可观测**：输入护栏（注入/偏见）+ HITL 高风险确认 + SSE 输出层 PII 脱敏 + Reflexion 工具结果反思重试 + AOP 全工具调用追踪 + token 落库。
7. **面试状态栏**：纯代码（无额外 LLM）将"已问维度/追问深度/剩余时长/阶段"读数注入 user 内容尾部，既给模型节奏感又不破坏 KV cache。
8. **格式差异驱动的简历解析 + 两阶段处理**：上传即得基础记录（正则毫秒级），耗时 LLM 分析/向量化走 MQ 异步；非空覆盖保护已有数据；按业务语义切块而非定长。
9. **统一 LLM 网关的 DeepSeek 推理模型兼容**：content/reasoning 双流，UI 可分思考/回答渲染；429 重试、stream usage、mock 全链路降级。

## 八、当前边界与已知缺陷

> 遵循"基于实际代码核验，不把设计预留/未接入写成既有成果"的原则，列出与宣传材料（`project-highlights.md`）表述不符或尚未闭环的点。

### 未接入生产链路（设计预留）
- **动态意图锚点自学习**：已接入但默认关闭灰度（`app.intent.dynamic-anchor.enabled=false`），开启后生效；非完全未实现。
- **统一离线评估体系与指标看板**：`EvaluationGoldenSample/EvaluationResult` 实体存在，但未接入生产链路；`project-highlights.md` 中"五策略 RAG 评估、Recall@5 0.69→0.75"等量化指标未在生产代码中复现。
- **自定义 Skill 系统**（`FileSystemSkillRepository` + 5 个招聘 Skill）：README「当前边界」列为后续演进项，未接入。
- **主动推送**：`EventController /subscribe/{userId}` 为 mock（发一次 session 后 empty），真实推送经 `ProactivePushService`，其生产触发链路待核验。
- **任务状态持久化**：`TaskStatusManager` 内存级，重启不可恢复；MQ 路径无重试/死信/幂等/重放治理。

### 代码级缺陷
- **Rerank 在匹配链路中为死代码**：`CandidateMatchService` 仅在 `pool.size() <= 10` 进入 rerank，但 `RerankService` 在 `documents.size() <= topN` 短路，而此处 `topN = docs.size()`，二者叠加使百炼 rerank 端点在匹配流程中从不被调用。（记忆检索链路中 `topN=5`，rerank 真正生效。）
- **匹配理由被硬编码丢弃**：`llmScore` prompt 请求了 `reason` 字段，但 `llmScore` 只返回三维分数，`match_details.reason` 写死为 `"LLM 三维评分 + 透明加权"`，无逐候选人自然语言理由。
- **意图阈值常量与 Javadoc 不符**：代码 `HIGH_THRESHOLD=0.90 / MID_THRESHOLD=0.65`，Javadoc 写 0.85/0.65，以代码为准。
- **岗位分析 Embedding 尽力而为**：`embeddingService.embed` 失败 `Throwable ignored` 吞掉，岗位可能仅有结构化字段无向量，迫使匹配 Stage-1 现场重算且不落库。
- **面试报告无 upsert**：`getReport` 每次 `reportMapper.insert`，重复调用产生重复报告行。
- **`endInterview` 不写终止状态**：仅 `currentRound += 1`，interview.status 仅出现过 pending/scheduled。
- **流式面试回答不回写**：`streamProcessAnswer` 不持久化会话消息，只有非流式 `processAnswer` 落库。
- **RerankService 失败抛异常**：注释称"降级"实为 `IllegalStateException`。
- **扫描件 PDF 无 OCR**；文件名/扩展名之外无 MIME/魔数/白名单校验；原始文件本体/哈希/解析版本未持久化；无上传去重。
- **`project-highlights.md` 中"37 个安全测试用例全通过""节省 90% token"等量化断言**未在代码中找到对应测试与度量闭环，使用时需另行评估。
